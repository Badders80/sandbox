# Chunk 3 — Deal assembly — DoD (locked 2026-11-10)

**Done when:** an operator creates or edits a DSL from existing Records through a
four-step wizard that ends in the term sheet, writes one `dsls` row, and the
PDS/SA compile from the deal's resolved soft content.

## Criteria

1. **Wizard.** `/dsl/new` and `/dsl/[id]/edit`: **Parties → Commercials → Terms →
   Narrative**, ending in the term-sheet **Review** (the Review is the popup, not
   a fifth step), one `<form>`, steps shown/hidden client-side, one submit at
   Confirm.
   Step 1 selects an existing horse, a trainer-role party and an owner-role party.
   A horse may hold several terms: show its existing DSLs and listed capacity for
   the operator's manual 100% check; do not exclude it. Read-only facts card. No
   authoring.
2. **Commercials (U7).** Two-way price: wholesale ⇄ retail; retail stays a whole
   dollar, rounded up; refuse when no whole-dollar wholesale reproduces it. Split,
   listed stake, minimum, step. Live derived strip. The 100% wholesale total never
   renders.
3. **Terms.** Start on the 1st, Expiry on the last day, derived months via
   `termMonthsBetween`; payment model filtered by `paymentModelAllowed`; close
   style; distribution schedule. Label **Expiry**, never "End date".
4. **Soft content (U14), four slots, three overridable.** Records own the base
   text: the horse profile gains one **Soft content** section with `aboutHorse`,
   `racingOutlookAndPedigree` and `raceExpectation` editable in place (writes the
   horse), and the trainer bio shown read-only with a link to the trainer's edit
   page. The wizard prefills all four; edits to the three horse slots are
   **deal-local overrides** on `dsls`, never written back. The **trainer bio is
   not overridable** — it always resolves from the party. Untouched slots read
   through from Records live (re-ruled 2026-11-10).
   **One resolver:** `resolveNarrative(horse, dsl, party)` returns
   `{ text, overridden }` per slot (override else Records). Readiness, the
   compiler, the term-sheet preview and the editor all import it; a SQL function
   encodes the same fallback for the trigger, and one test proves TS and SQL
   agree on a fixture set.
5. **Override warning.** Per slot store the override text, the Records source hash
   at edit time, and the dismissed hash. On `/dsl/[id]`, if the current Records
   hash differs and has not been dismissed, one banner lists the affected slots;
   one **Dismiss** action stores the dismissed hash for that source state.
   Informational, never blocks. No model, no cron.
6. **Approve.** Lives on the deal. Writes `narrative_signoff`,
   `narrative_approved_at`, `narrative_approved_hash`. Refused while any of the
   four resolved slots is empty. The hash covers the four **resolved** texts
   (three override-resolved plus the party bio), canonicalised — never the raw
   Records values.
7. **Review (U4).** Term sheet from `buildTermSheet`: parties, horse facts, every
   commercial number, term/expiry, resolved soft content, readiness gaps. Three
   actions: Confirm · Edit · Close. Edit returns to the owning step; Close writes
   nothing.
8. **Draft documents (U10).** `/dsl/[id]/legal` gains the **DRAFT — not executed**
   banner and the blocking-field list on failure.
9. **Migration `00022`.** Three nullable text columns on `dsls`
   (`narrative_about_horse`, `narrative_racing_outlook`,
   `narrative_race_expectation`), plus `narrative_override_meta jsonb` holding
   per-slot `sourceHash`/`dismissedHash` with a CHECK that its keys are a subset
   of the three, plus `check (role in ('trainer','owner'))` on `party_roles`.
   **H6 (sales append-only) moves to `00023`.**
10. **The `/dsl` list** reads Horse · Price · Investor · Return % · Expiry ·
    Status (delivered ahead, `0d912d9`). A deal is identified
    `Horse | Price | Investor Return % | Expiry`.
