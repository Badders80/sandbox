## 3. Is "steps 1–9 + DSL engine = clean runway" true?

**Almost.** Three things sit outside that pair and block the gate:

1. **Five seam blockers are money-path defects in steps 7–8, not DSL-engine defects.** Fixing the DSL engine fixes the readiness gate. It does not fix amount binding, webhook concurrency, or the image recheck at purchase.
2. **No data spine.** The six horses exist only as local rows created on 2026-10-23, not reproducible from git. A preview with no content proves nothing.
3. **No legal proof.** The NZTR reference set is absent from the repo and the required disclosure self-audit was never recorded. `OUTCOME.md` and the compiler both point at a checklist that is not there.

## 5. Proposed chunking

Each chunk ends at its own gate. Do not start the next on a red gate.

**10.0 — Close the audit blockers.** Repo private. Commit `00013`. Fix the five seam blockers: one readiness gate shared by save/publish/compile; image recheck at purchase; bind the charge to the compiled row (session metadata carries the quote, or store a quote id); read `amount_total` from Stripe; serialise the `stake_remaining` drawdown. Gate: `pnpm verify` + a new test per blocker.

**10.1 — Ratify the documents.** Amend `OUTCOME.md`, `PLAN.md`, `CONTINUE.md`: the DSL-engine model decisions, the 10-23 chunking, and this plan. Gate: the three files agree with each other and with the code.

**10.2 — DSL engine.** Per `DSL-ENGINE-BRIEF-2026-11-07.md` §6. Gate: content readiness function with tests; trainer/owner edits persist; projection published.

**10.3 — Data spine.** A remote Supabase project; migrations 00001–00013 applied by script; six horses entered through the DSL page; two reach Available; one deliberately refused. Gate: a fresh clone plus the script reproduces the six rows.

**10.4 — Legal proof.** Reference set and checklist into `docs/legal/reference/`; self-audit run and recorded against both rendered documents. Gate: the audit output is in `engine/OPERATIONS.md` with the pack version.

**10.5 — Local money walk.** Stripe test keys and `stripe listen`; the full five screens; verify sale row, frozen hashes, four emails, MyStable. Then the failure walk: KYC fail, checkout cancel, card decline, duplicate webhook. Gate: a written walk record, not a claim.

**10.6 — Preview deploy.** Two Vercel projects, `WEBSITE_BUY_ENABLED=false`, six-horse marketplace and horse pages, screenshot gate at 1440×900 and 390×844. Gate: founder's eye on the preview.

**10.7 — Visual parity.** Bounded copy from the old site. No redesign.

**10.8 — Cutover and the DoD.** Flip the flag, point the domain, **one real sale**, verify frozen hashes, amount, MyStable, emails. Archive the old app; do not delete old data.
